# 常见错误与排查

均为本工程实际遇到过的问题，按出现频率排序。

## 1. 编译报 umbrella header not found（ThingModuleServices）

```
error: 'ThingModuleServices/ThingModuleServices-umbrella.h' file not found
```

**原因**：涂鸦 `ThingModuleServices 5.2.1.4` 的二进制包本身缺 umbrella 头文件（5.1.x / 4.76.x 均正常）。升级 SDK 大版本时依赖解析容易落到这个坏版本。

**解法**：Podfile 固定版本，不要动：

```ruby
pod 'ThingModuleServices', '4.76.6'
```

改完后执行 `pod update ThingModuleServices`。

## 2. required a higher minimum deployment target

```
Specs satisfying ... required a higher minimum deployment target.
```

**原因**：AppIOSBase 0.2.0（涂鸦 7.11 线）要求 iOS 14.0，Podfile 还是 `platform :ios, '13.0'`。

**解法**：三处全部对齐 14.0：
1. Podfile 的 `platform :ios, '14.0'`
2. Podfile `post_install` 里 `IPHONEOS_DEPLOYMENT_TARGET = '14.0'`
3. `project.yml` 的 `deploymentTarget.iOS` 与 `IPHONEOS_DEPLOYMENT_TARGET`

## 3. CocoaPods 依赖快照冲突

```
CocoaPods could not find compatible versions for pod "ThingSmartMQTTChannelKit":
In snapshot (Podfile.lock): ... In Podfile: ...
You should run `pod update ...`
```

**原因**：Podfile 依赖约束变了，但 Podfile.lock 的旧快照锁住了子依赖版本。

**解法**：按提示 `pod update <Pod 名>`；升级大版本直接全量 `pod update`。

## 4. No Accounts / No profiles for 'com.lock.set'

CLI 构建或新机器上报：

```
error: No Accounts: Add a new account in Accounts settings.
error: No profiles for 'com.lock.set' were found
```

**解法**：Xcode → Settings → Accounts 登录 Apple 开发者账号；Signing & Capabilities 选 Team 后真机直跑。命令行只验证编译可用：

```bash
xcodebuild ... CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build
```

## 5. Apple Silicon 模拟器无法运行

SDK 的二进制无 arm64 模拟器切片，启动即崩或链接失败。

**解法**：Podfile 已通过 `EXCLUDED_ARCHS[sdk=iphonesimulator*] = arm64` 兜底可编译 x86_64 模拟器，但**联调请一律用真机**。

## 6. 运行时报 ILLEGAL_CLIENT_ID

**原因**：平台配置与工程不匹配——Bundle ID 不一致，或平台绑定的 SHA256 与当前签名不符。

**解法**：核对 Bundle ID（默认 `com.lock.set`）；在 IoT 平台重新登记当前证书的 SHA256。

## 7. 运行时报 SING_VALIDATE_FALED（签名校验失败）

**原因**：AppKey / AppSecret 与平台不一致，或工程残留旧版 `t_s.bmp` 安全图片。

**解法**：核对 `LocalSecrets.plist` 与平台信息；删除旧安全图片；升级自 3.x/4.x 时尤其注意。

## 8. 登录后设备列表为空 / 面板不打开

- 设备列表数据来自 AppIOSBase，确认 `:tag => '0.2.0'` 及以上（早期版本没有家庭/设备能力）。
- 门锁面板走 `Base.devicePanelHandler` 回调，确认宿主 AppDelegate 注册了该钩子。
